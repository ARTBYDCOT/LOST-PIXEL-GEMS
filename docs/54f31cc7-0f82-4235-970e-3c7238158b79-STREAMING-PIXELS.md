# STREAMING PIXELS (SPIXELS) — documentation

A self-running **weekly PIXEL reward faucet** for the Lost Pixel ecosystem. PIXEL (an ERC-1155 NFT token) is deposited into the contract; **holders of GEMS V1, GEMS V2 or LPC-BOT** claim a **fully random 1–11 PIXEL** reward **once per week**. It runs forever, week after week, while the pool holds PIXEL.

### Program stages / expansion

The faucet is designed to grow in **phases**. Each phase is simply a top-up (and, optionally, tuned parameters or new eligible collections) — the same contract keeps running, no redeploy needed.

| Stage | PIXEL added | What it enables |
|---|---|---|
| **Stage 1 · first expansion** | **99,999 PIXEL** | Launches the weekly faucet for GEMS V1/V2 & LPC-BOT holders. |
| Stage 2+ (future) | top-up as needed | Extends the runway; may add new eligible collections, adjust `maxReward` or the weekly cadence. |

Because the contract is permanent and epoch-based, expanding the program is a **single `deposit`** (and optional `addCollection` / `setMaxReward` / `setWeek`) — holders keep claiming without interruption.

## How it works

- **Weekly epochs from deploy.** `startTime` is set at deployment; each epoch is `week` = 7 days. `currentWeek() = (now − startTime) / week`. The clock is global and automatic — no admin action advances it.
- **Live owner snapshot.** Eligibility is read **at claim time** with `balanceOf`, so it always reflects the **current owners** — an automatic per-week snapshot without storing a holder list on-chain.
- **One claim per wallet per week.** Tracked by `claimedInWeek[week][wallet]`.
- **Fully random reward.** `amount = 1 + (rand % maxReward)` with `maxReward = 11`. Nobody wins more than 11 PIXEL in a week.
- **Capped at the pool.** If the reward would exceed what's left, it's capped to the remaining balance — so **if only 1 PIXEL remains, the first wallet to sign gets it**.
- **Runs forever.** As long as the pool holds ≥1 PIXEL, claims keep working every week.

Randomness is on-chain pseudo-random (`block.prevrandao + sender + nonce`) — appropriate for a low-value weekly faucet, not for high-value security.

## For holders — how to claim

1. Open **https://lostpixelgems.space/streaming.html** and **connect your wallet**.
2. If you hold a **GEMS V1/V2 or LPC-BOT**, you'll see you're **eligible** and the week's countdown.
3. Press **🔥 RECLAMAR SUMINISTRO SEMANAL DE PIXELS**.
4. Confirm the transaction — you receive a **random 1–11 PIXEL**.
5. Come back **next week** to claim again. Your rank appears in the live global ranking.

You pay only network gas. Nothing is burned; PIXEL is transferred to you from the pool.

| Action | Function | Notes |

| Change week length | `setWeek(uint256 seconds)` | default 604800 (7 days) |
| Change PIXEL token | `setPixel(token, id)` | |

> ⚠️ On deploy the allow-list and pool start empty. To go live you must **add the collections** and **deposit PIXEL** — otherwise `isEligible` is false for everyone and `claim()` reverts with `pool empty`.

## Running out / refueling

Each claim decrements the pool. When the balance drops below the random draw it pays out **whatever is left** (down to the last PIXEL), then further claims revert with `pool empty - refuel PIXEL`. To continue, the admin opens the **next stage** by simply **depositing more PIXEL** (a Stage 2+ top-up, in the spirit of the 99,999 Stage 1 seed) — claims resume automatically in the current week, no redeploy or migration.
